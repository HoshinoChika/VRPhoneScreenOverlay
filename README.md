## 项目简介

VRPhoneScreenOverlay 面向 **Windows PC + SteamVR + Android 手机** 的使用场景，将手机画面显示为 VR 浮窗，并通过 VR 控制器操作手机。

项目关注的是在 VRChat 等 SteamVR 使用场景中，无须摘下头显就能查看和操作自己的手机。它不是 VRChat 世界内的播放器，也不是上传到 Avatar 的屏幕材质：**本机看到的浮窗不会自动同步给房间里的其他人。** 好友共同观看属于后续独立的联网共享功能。

| 本地使用 | 交互体验 | 后续方向 |
| :--- | :--- | :--- |
| Android 手机通过 USB 接入电脑 | VR 触摸、滚动、系统按键 | 配对码邀请好友只读观看 |
| 手机视频与音频分别处理 | 浮窗抓取、移动、缩放 | P2P 优先，按需评估服务器中转 |
| SteamVR 中显示手机浮窗 | 独立的空间拖拽能力 | 多人共享与发送前隐私遮挡 |

## 快速上手

> 下列是基于历史版本整理的使用流程。需要先取得对应可运行版本；当前只有本首页，不能直接运行或编译本项目。

1. **准备电脑与 VR 环境。** 启动 SteamVR，确认头显和控制器能正常工作。
2. **连接 Android 手机。** 使用支持数据传输的 USB 线，开启 USB 调试，并在手机上确认对自己电脑的调试授权。[3]
3. **运行项目程序。** 使用对应版本的 Windows 发行包启动程序，完成手机连接；界面位置以该版本说明为准。
4. **调整浮窗与输入。** 在 VR 中查看手机画面，按 SteamVR 绑定进行触摸、抓取、缩放与滚动；需要时在 SteamVR 绑定界面修改按键。
5. **检查声音与权限。** 音频路线面向 Android 11+；Android 11 启动采集时需保持手机解锁。遇到无声或无法触摸时，分别检查系统能力、输出设备和手机输入权限。[2][3]

**USB 调试只应授权给可信电脑。** 分享截图或诊断信息前，先移除手机通知、聊天内容、设备标识与其他私人信息。

## 技术路线

### 1. 本地链路：以既有实现为基础

| 层次 | 历史基线技术 | 职责 |
| :--- | :--- | :--- |
| 应用与模块 | C# / .NET，多项目分层 | 应用编排、设置、平台适配与接口边界 |
| Android 接入 | USB ADB + scrcpy 4.1 服务端 | 设备连接，独立视频、音频和控制会话 |
| 视频处理 | H.264 → Media Foundation → D3D11 | 视频解码、纹理转换与提交 |
| VR 显示 | OpenVR Overlay | 将手机画面显示为 SteamVR 浮窗 |
| 音频处理 | Opus → Concentus → WASAPI | 手机音频解码与 Windows 播放 |
| 输入处理 | SteamVR Actions → 有界输入调度 → scrcpy control | 触摸、系统按键与交互动作 |
| 空间拖拽 | OpenVR Chaperone 工作空间姿态 | 调整空间偏移，与浮窗位置独立 |

```text
Android 手机
    │ USB / ADB
    ├─ 视频会话 → H.264 → Media Foundation → D3D11 → OpenVR 浮窗
    ├─ 音频会话 → Opus → Concentus → WASAPI → 电脑音频输出
    └─ 控制会话 ← 输入调度 ← SteamVR Actions ← VR 控制器

空间拖拽：控制器位移 → 独立拖拽服务 → OpenVR 空间偏移
```

沿用“最新帧优先”和有界队列的设计方向，避免忙碌时持续堆积旧画面。视频、音频和控制分别管理，后续网络功能不应阻塞本地 VR 显示与操作。

**需要保留的技术边界：** 历史视频链路仍有 CPU 帧缓冲与 GPU 上传，不能宣传成已经完成全链路 GPU 零拷贝。GPU 原生解码与纹理直通应作为后续优化项验证。

### 2. 1 对 1 共享：候选路线，尚未实现

拟以**分享者电脑**作为媒体发送端，好友电脑作为接收端；手机仍通过本地 USB 链路接入分享者电脑。

```text
Android 手机 → 分享者电脑 → 发送前隐私处理 → 共享编码 / 打包
                                              │
                              优先 WebRTC P2P ─┴─→ 好友客户端

分享者电脑 ←─ 配对码、授权、连接协商 ─→ 信令服务 ←─→ 好友客户端

无法直连时：明确报告连接失败，或按后续策略使用可选 TURN 中继
```

候选分工如下，具体库和部署方案尚未选定：

| 组件 | 候选职责 | 不应混淆的边界 |
| :--- | :--- | :--- |
| 配对 / 信令服务 | 会话登记、短期配对码、授权状态、交换连接协商信息 | 信令不是媒体转发；配对码不能代替完整鉴权 |
| WebRTC + ICE / STUN | 协商音视频能力并尝试建立直连 | 不能保证所有网络都成功打洞 [4] |
| 可选 TURN | 无法直连时中继媒体数据 | 会产生服务器媒体流量，不再是“服务器只传配对码” [5] |
| 接收客户端 | 接收、解码并显示好友共享画面 | 不自动变成 VRChat 世界或 Avatar 的同步内容 |

**“不经过 VPS 转发音视频”只适用于成功直连的媒体路径。** 信令仍有少量服务器流量；启用中继后，必须单独考虑带宽、流量与费用。

原始 H.264 码流是否可复用，要看编码参数、关键帧与网络适配。**一旦需要黑屏、模糊或其他画面改写，就不能直接把未经处理的原始码流发给好友**；需要在发送路径处理帧并按需重新编码。

### 3. 1 对多与隐私保护：后续评估

少量观看者可先评估多路 P2P，但分享者的上行负担会随连接数增加。更大规模再评估 SFU 转发，依据实测码率、观看人数和出口流量选择服务配置；首页暂不写死人数上限、服务器价格或套餐。

隐私保护的候选原则是：**先处理、再发送；检测异常时优先暂停。** 指定 App 的识别方式、分屏 / 悬浮窗、切换瞬间、通知、音频以及编码队列都需要覆盖测试，不能仅依赖低频检测前台应用，也不能只在分享者的本地窗口上盖一层黑色。此功能尚未实现，不应据此共享敏感信息。

## 常见问题

### 为什么有项目介绍，却还没有下载包？

本仓库是新建的私有仓库，本次先补项目首页。历史项目已经有本地实现记录，但对应源码、发行包和设备测试结果尚未同步到这里。

### 在 VRChat 中打开后，好友会直接看到我的手机吗？

不会。当前基线是本机 SteamVR 浮窗。好友共同观看需要后续的共享发送端、接收端与授权机制；仅处于同一个 VRChat 房间不会自动共享屏幕。

### PICO / Quest 一体机可以直接安装吗？

本项目当前是 Windows PC 侧工具，不是一体机应用。通过电脑运行 SteamVR 的设备应按实际控制器类型和实机测试结果判断，不能把存在默认绑定等同于某款头显已经验证兼容。

### 无线连接和 iPhone 是否已经支持？

未列入当前基线实现。scrcpy 上游的功能列表不等于本项目的功能列表。[3]

### 为什么手机没有声音或无法操作？

Android 10 及以下不提供当前路线的内部音频采集；Android 11 需要注意启动时的解锁状态。部分手机系统还要求额外的输入控制授权。具体故障应结合项目版本、手机系统与错误信息排查。[2][3]

不会。本次只添加仓库根目录的 `README.md`，不修改可见性，不启用 GitHub Pages，也不自动发布软件。GitHub 会将 README 显示在仓库首页，访问仍由仓库权限控制。[1][6]
